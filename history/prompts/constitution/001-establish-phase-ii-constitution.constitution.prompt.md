## Prompt

Phase II Constitution — Full-Stack Todo Web Application

Purpose
This constitution governs Phase II of the "Evolution of Todo" project. Phase II evolves the Todo system into a full-stack web application using strict Spec-Driven Development. This phase focuses on clean architecture, persistence, and API governance without introducing any AI or cloud-native orchestration.

Spec-Driven Development Rules

All application code MUST be generated exclusively by Claude Code.

Manual writing or editing of implementation code is strictly forbidden.

Specifications are the single source of truth.

If generated output is incorrect, incomplete, or suboptimal, the specification MUST be refined instead of modifying code.

Each generation must be deterministic and reproducible from the specification.

Architectural Principles

The system MUST follow a strict client–server architecture.

Frontend and backend MUST be fully decoupled.

All business logic, validation, and data rules MUST reside in the backend.

The frontend MUST act only as a presentation and interaction layer.

Communication between frontend and backend MUST occur exclusively via RESTful HTTP APIs.

Frontend Constraints

Framework: Next.js using the App Router.

Language: TypeScript.

The UI MUST be minimal, functional, and form-based.

The frontend MUST NOT contain business logic or database logic.

Client-side validation MUST be limited to basic form validation only.

No AI, natural language, or automation logic is permitted in the frontend.

Backend Constraints

Framework: FastAPI.

Language: Python.

Data models MUST be defined using SQLModel.

The backend MUST expose RESTful endpoints only.

API behavior MUST be deterministic and stateless.

No GraphQL, WebSockets, background workers, or message queues are allowed.

Database Constraints

Database: Neon Serverless PostgreSQL.

Persistent storage is mandatory.

Schema-first design MUST be followed.

Database connection details MUST be managed via environment variables.

The database schema MUST support future AI-driven interactions without modification.

Feature Scope (Phase II Only)

Create, read, update, and delete Todo items.

Toggle task completion status.

Assign priority levels (high, medium, low).

Assign tags or categories to tasks.

Search tasks by text.

Filter tasks by status and priority.

Sort tasks by priority, title, or creation time.

Explicit Exclusions

No AI agents, chatbots, or language models.

No natural language input or interpretation.

No Kubernetes, Docker, or container orchestration.

No event-driven architecture, Kafka, or Dapr.

No voice input or multimedia features.

Quality & Reliability Standards

API responses MUST use clear and consistent HTTP status codes.

Error handling MUST be explicit and predictable.

Input validation MUST be enforced at the backend boundary.

Generated code MUST be readable, modular, and production-oriented.

Evolution Readiness

The system design MUST remain extensible for AI integration in Phase III.

Data models and API contracts MUST remain stable
